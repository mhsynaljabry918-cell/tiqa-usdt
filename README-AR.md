# أساس الخادم الخلفي لمشروع ثقة USDT

هذه حزمة تأسيسية مستقلة للانتقال من المحاكاة الموجودة في HTML إلى خادم وقاعدة بيانات حقيقيين. **لم يتم تعديل ملف الواجهة الأصلي**.

## ما أُنجز في هذه الدفعة

- خادم API باستخدام Node.js وExpress.
- مخطط PostgreSQL للحسابات ورموز التحقق والجلسات والإدارة والصلاحيات وسجل التدقيق. تُطبّق ملفات الترحيل المرقمة تلقائياً وبالترتيب.
- إضافة مخطط بيانات أساسي للتجار ومعرّفاتهم وملفاتهم العامة والتقييمات والردود والبلاغات وسجل حالاتها والاعتراضات ومطالبات الملكية وطلبات توثيق الهوية وبيانات الأدلة الخاصة ونطاقات الدول.
- إنشاء حساب بالبريد أو الهاتف مع OTP.
- تسجيل الدخول والتحقق من OTP.
- حفظ الجلسات في قاعدة البيانات مع كوكي HttpOnly.
- إبطال الجلسة عند تسجيل الخروج.
- أساس أدوار وصلاحيات الإدارة على الخادم.
- تسجيل دخول إداري بكلمة مرور مجزأة باستخدام bcrypt، دون قائمة مشرفين تجريبية.
- تحديد معدل طلبات المصادقة وحماية HTTP الأساسية.

## ما لم يصبح فعالاً بعد

- لا يوجد اتصال بقاعدة بيانات حتى تضبط `DATABASE_URL` وتشغّل الترحيل.
- يمكن في الاختبار ضبط `OTP_DELIVERY_MODE=console` لطباعة OTP في سجلات الخادم؛ لا تستخدم هذا الوضع مع مستخدمين حقيقيين.
- أُضيف ملف واجهة مستقل `TiqaUSDT-Auth-Integrated.html` يوجّه إنشاء الحساب وتسجيل الدخول والتحقق وتسجيل الخروج ودخول الإدارة إلى API الحقيقي عند ضبط `window.TIQA_API_BASE`. لا تُظهر الواجهة رمز OTP التجريبي ولا قائمة المشرفين التجريبية.
- بعد دخول المشرف الحقيقي، تعرض الواجهة إشعاراً واضحاً بأن أقسام الإدارة التشغيلية لم تُربط بعد؛ ولا تعرض بيانات المحاكاة على أنها بيانات حقيقية.
- تسجيل دخول الإدارة متاح عبر `POST /api/admin/login` بكلمة مرور المشرف. جداول نطاقات الدول موجودة، لكن فرض النطاق وتسجيل جميع إجراءات الإدارة لم يُربطا بعد بمسارات الإدارة.
- جداول التجار والتقييمات والبلاغات والاعتراضات أصبحت معرفة في قاعدة البيانات، لكن عمليات API الخاصة بها لم تُنفّذ بعد ولم تُنقل بيانات المحاكاة إليها.
- لا تعتبر هذه الحزمة جاهزة للإنتاج قبل مراجعة أمنية واختبارات تكامل ونشر HTTPS ونسخ احتياطي.

## نشر تجريبي مجاني على Render + Neon

- الواجهة أصبحت داخل `public/index.html` وتُقدَّم من نفس عنوان الخادم؛ لا تحتاج إلى تعديل رابط API أو استضافة واجهة منفصلة.
- أنشئ PostgreSQL على Neon، ثم ضع رابط الاتصال `DATABASE_URL` في متغيرات Render مع `sslmode=require`.
- ارفع محتويات هذا المجلد إلى مستودع GitHub، ثم أنشئ Web Service على Render واربط المستودع. يمكن استخدام `render.yaml` كإعداد أولي.
- Build Command: `npm install && npm run db:migrate`.
- Start Command: `npm start`.
- أضف `DATABASE_URL` و`OTP_PEPPER` في Environment. إن لم تستخدم ملف `render.yaml`، أضف أيضاً `NODE_ENV=production` و`COOKIE_SECURE=true` و`COOKIE_SAME_SITE=lax` و`OTP_DELIVERY_MODE=console` و`ALLOW_INSECURE_OTP_LOGS=true`.
- بعد النشر افتح `https://عنوان-الخادم.onrender.com/` للواجهة و`/api/health` لفحص اتصال قاعدة البيانات.
- عند طلب التسجيل أو الدخول، افتح Render ثم Logs وابحث عن `TIQAUSDT TEST OTP` لقراءة الرمز.

**تنبيه OTP:** وضع Console مؤقت للاختبار فقط؛ الرمز يظهر لأي شخص لديه صلاحية الاطلاع على سجلات الخادم. عطّله قبل دعوة مستخدمين حقيقيين، ولا تشارك السجلات أو الرمز.

**حدود المجانية:** خدمة Render المجانية تتوقف بعد 15 دقيقة دون طلبات وقد يستغرق إيقاظها نحو دقيقة. Neon Free يتضمن حدود استخدام شهرية ومساحة تخزين محدودة؛ راقب لوحة Neon. لا تستخدم بيانات حقيقية أو حساسة في هذه التجربة.

## المتطلبات

- Node.js 20 أو أحدث.
- PostgreSQL 14 أو أحدث.
- حساب SMTP لإرسال البريد، و/أو حساب Twilio لإرسال SMS.

## التشغيل

1. فك ضغط الحزمة.
2. انسخ `.env.example` إلى `.env`.
3. املأ `DATABASE_URL` وأنشئ قاعدة بيانات فارغة باسم `tiqa_usdt`.
4. أنشئ قيمة عشوائية طويلة لـ `OTP_PEPPER` (32 حرفاً أو أكثر).
5. شغّل:

```bash
npm install
npm run db:migrate
npm run dev
```

6. اختبر:
   - `GET http://localhost:3000/api/health`
   - `POST http://localhost:3000/api/auth/signup/request`
   - `POST http://localhost:3000/api/auth/verify`
   - `GET http://localhost:3000/api/auth/me`

## ملاحظات أمنية

- لا تضع مفاتيح SMTP أو Twilio أو قاعدة البيانات داخل HTML أو JavaScript الذي يصل للمتصفح.
- لا ترفع ملف `.env` إلى Git أو تشاركه.
- استخدم HTTPS و `COOKIE_SECURE=true` في الإنتاج.
- إعداد CORS يجب أن يحتوي نطاق الواجهة الفعلي فقط.
- لا تستخدم بيانات مشرفين تجريبية؛ أنشئ مشرفاً بكلمة مرور قوية عبر `npm run admin:create`.
- لا تُدخل بيانات حقيقية للمستخدمين قبل اختبار تدفق المصادقة وسياسة الخصوصية.


## ربط ملف الواجهة بالمصادقة

1. انشر الخادم أولاً على عنوان HTTPS.
2. افتح `TiqaUSDT-Auth-Integrated.html` في محرر نصوص، وابحث عن `window.TIQA_API_BASE =` وضع عنوان API الحقيقي بين علامتي الاقتباس، مثل `https://api.example.tld` (استبدل المثال بعنوانك الفعلي).
3. يجب أن يتضمن `FRONTEND_ORIGIN` في `.env` أصل موقع الواجهة الفعلي، وأن يكون الموقع والخادم على HTTPS في الإنتاج مع `COOKIE_SECURE=true`.
4. لا تفتح الملف محلياً بصيغة `file://` عند اختبار الكوكيز؛ استضف الواجهة على أصل ويب مسموح في CORS.
5. في الاختبار السحابي، اقرأ OTP من سجلات Render عند تفعيل وضع Console. لا توجد رموز تظهر على الشاشة.

**حدود هذه النسخة:** المصادقة الحقيقية للمستخدمين والمشرفين موصولة فقط. بقية عمليات التجار والتقييمات والبلاغات ولوحات الإدارة ما زالت تعتمد على النموذج المحلي ولم تُنقل إلى API بعد. لا تدخل بيانات حقيقية ولا تعتبرها منصة منشورة أو جاهزة للإنتاج.
